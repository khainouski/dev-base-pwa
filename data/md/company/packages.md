## encoding/json

Используется для кодирования и декодирования JSON. Есть два способа работы — через `[]byte` в памяти или потоково через `io.Reader`/`io.Writer`.

### Способ 1: Marshal / Unmarshal (через `[]byte`)

Просто и подходит для небольших данных, которые уже целиком в памяти.

```go
data, err := json.Marshal(v)      // Go-структура → []byte с JSON
err := json.Unmarshal(data, &v)   // []byte с JSON → Go-структура
```

Пример: нужно вернуть JSON-ответ из HTTP-хендлера как строку или положить JSON в переменную.

### Способ 2: Encoder / Decoder (потоково)

Эффективнее для больших данных или когда JSON нужно писать/читать сразу из сети или файла, без промежуточного `[]byte`.

```go
encoder := json.NewEncoder(w)   // w — io.Writer
err := encoder.Encode(v)        // Go-структура → JSON, сразу в w

decoder := json.NewDecoder(r)   // r — io.Reader
err := decoder.Decode(&v)       // JSON из r → Go-структура
```

Пример: чтение JSON-тела запроса `r.Body` в HTTP-хендлере или запись JSON-ответа прямо в `http.ResponseWriter`.

## context

Используется для отмены операций, таймаутов и передачи данных в рамках запроса.

Создание:

```go
ctx := context.Background()
ctx, cancel := context.WithTimeout(ctx, time.Second)
```

Популярные методы:

- `context.Background()` — базовый контекст
- `context.WithTimeout(ctx, duration)` — создаёт контекст с таймаутом
- `context.WithCancel(ctx)` — создаёт отменяемый контекст

## os / io

Работа с файлами, потоками и системными операциями.

Создание:

```go
file, _ := os.Create("file.txt")
file, _ := os.Open("file.txt")
```

Популярные методы:

- `os.Open(name)` — открывает файл
- `os.Create(name)` — создаёт файл
- `io.ReadAll(r)` — читает все данные из reader

## testing

Пакет для написания тестов.

Создание:

```go
func TestSomething(t *testing.T) {}
```

Популярные методы:

- `t.Run(name, func)` — запускает подтест
- `t.Errorf(...)` — логирует ошибку без остановки теста
- `t.Fatal(...)` — логирует ошибку и останавливает тест

Пакет `testing` используется для:

- unit тестов ✅

## net/http

Стандартный пакет для создания HTTP серверов и клиентов.

### Сервер

```go
http.ListenAndServe(addr, handler)   // запускает HTTP сервер
```

Основные типы для обработки запросов:

- `http.Handler`, `http.HandlerFunc` — обработчики запросов
- `http.ResponseWriter` — запись ответа клиенту
- `http.Request` — данные входящего запроса

### Клиент

```go
client := &http.Client{}
client := &http.Client{Timeout: 5 * time.Second}
```

Популярные методы:

- `client.Get(url)` — отправляет GET-запрос через клиент
- `http.NewRequest(method, url, body)` — создаёт HTTP запрос (для методов кроме GET, кастомных заголовков и т.д.)
- `http.Transport` — настройка транспорта клиента (таймауты, keep-alive, прокси)

## TCP-клиент

Создание соединения:

```go
conn, err := net.Dial("tcp", address)
```

Чтение данных:

```go
message, err := bufio.NewReader(conn).ReadString('\n')
```

`bufio` используется для буферизированного чтения.

```go
conn, err := net.DialTCP("tcp4", nil, tcpAddr)
```

## Unix Domain Socket (UDS)

**Unix Domain Socket** — сокет для обмена данными между процессами **на одном компьютере**.

Особенности:

- работает только локально;
- не использует IP и TCP — данные передаются через ядро ОС;
- вместо IP-адреса используется файл.

Пример адреса — путь к файлу, а не `IP:порт`:

| TCP                 | Unix Socket                          |
|---------------------|---------------------------------------|
| `192.168.1.15:5432` | `/var/run/postgresql/.s.PGSQL.5432`  |

### Создание Unix Socket сервера

1. Выбрать путь и удалить старый сокет, если остался:

   ```go
   socketPath := "/tmp/app.sock"
   os.Remove(socketPath)
   ```

2. Создать сервер (при вызове ОС сама создаёт файл-сокет) и принять подключение:

   ```go
   listener, err := net.Listen("unix", socketPath)
   conn, err := listener.Accept()
   ```

3. Читать и писать:

   ```go
   conn.Read(...)
   conn.Write(...)
   ```

4. При завершении — закрыть сервер и убрать за собой файл сокета:

   ```go
   listener.Close()
   os.Remove(socketPath)
   ```

### Клиент

```go
conn, err := net.Dial("unix", "/tmp/app.sock")
```

## WebSocket

**WebSocket** работает поверх TCP (`WebSocket → TCP → IP → Ethernet/Wi-Fi`) и позволяет серверу самостоятельно отправлять сообщения клиенту без новых HTTP-запросов. Типичные сценарии: чаты, онлайн-игры, уведомления, биржевые котировки, совместное редактирование документов.

### Как работает

1. Клиент отправляет HTTP-запрос.
2. Сервер выполняет Upgrade HTTP → WebSocket.
3. Устанавливается постоянное TCP-соединение.
4. Клиент и сервер обмениваются сообщениями в обе стороны без новых запросов.

### WebSocket в Go

Стандартная библиотека WebSocket не поддерживает — обычно используют `github.com/gorilla/websocket`:

```go
upgrader.Upgrade(...)   // Upgrade HTTP → WebSocket
conn.ReadMessage()      // чтение сообщения
conn.WriteMessage()     // отправка сообщения
conn.Close()            // закрытие соединения
```

### HTTP vs WebSocket

| HTTP                              | WebSocket                              |
|------------------------------------|-----------------------------------------|
| Request → Response                 | Полный двусторонний обмен               |
| Соединение обычно короткое         | Постоянное соединение                   |
| Сервер отвечает только на запрос   | Сервер может отправлять сообщения сам   |
| REST API                           | Чаты, стриминг, игры, уведомления       |

## Работа с REST API

**REST (Representational State Transfer)** — архитектурный стиль построения веб-сервисов. Он определяет принципы взаимодействия клиента и сервера, а не конкретный протокол.

### REST ≠ JSON

REST **не требует JSON**. В качестве формата данных можно использовать:

- JSON;
- XML;
- HTML;
- Protocol Buffers;
- текст и др.

### REST ≠ HTTP

REST **не привязан к HTTP**, но на практике почти все REST API работают поверх HTTP/HTTPS.

### Что такое RESTful

**RESTful API** — API, которое следует принципам REST:

- ресурсы имеют URI (`/users/1`);
- используются HTTP-методы (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`);
- сервер не хранит состояние клиента (**Stateless**);
- используются стандартные HTTP-коды (`200`, `201`, `404`, `500`).

Пример:

```text
GET    /users
GET    /users/1
POST   /users
PUT    /users/1
PATCH  /users/1
DELETE /users/1
```

## Разные вопросы

### Что такое `go:generate`?

`go:generate` — специальная директива в комментарии, которая позволяет запускать команды генерации кода. Выполняется только командой:

```bash
go generate
```

Чаще всего используется для генерации:

- моков (`mockgen`, `mockery`);
- protobuf-кода (`protoc`);
- строковых представлений enum (`stringer`);
- кода по OpenAPI/Swagger.

Пример:

```go
//go:generate mockgen -source=service.go -destination=mock_service.go
```

### Сборщик мусора

Сборщик мусора (**GC**) автоматически освобождает память от объектов, которые больше не используются.

В Go применяется алгоритм **трёх цветов**:

- **белые** — ещё не проверены;
- **серые** — найдены, но их ссылки ещё проверяются;
- **чёрные** — проверены и используются.

После обхода оставшиеся белые объекты считаются недоступными, и их память освобождается.

### epoll

epoll — механизм Linux для эффективного ожидания событий на большом количестве файловых дескрипторов (сокетов, файлов, каналов).

**Какую проблему решает.** Без `epoll` приложение должно постоянно проверять каждый сокет:

```text
socket1?
socket2?
socket3?
...
```

При тысячах соединений это создаёт лишнюю нагрузку на CPU.

С `epoll` ядро само сообщает, какие сокеты готовы к чтению или записи:

```text
100 000 соединений
        ↓
      epoll
        ↓
Готовы: socket5, socket900
```

**Зачем нужен:**

- эффективно обслуживать тысячи соединений;
- не тратить CPU на постоянный опрос сокетов;
- использовать событийную (event-driven) модель ввода-вывода.
