# Go 1.27 — что нового (вышел 20 августа 2026)

## 1. Generic methods — методы теперь могут быть generic

С 1.18 действовало ограничение: **метод не мог объявить свой type-параметр** — то есть `[...]` после имени метода писать было нельзя.

Пример: конфиг, который хранит всё строками, а отдавать должен нужным типом.
```go
type Config struct {
    values map[string]string
}

// ❌ до 1.27: method must have no type parameters
func (c *Config) Get[T int | string | bool](key string) T { ... }

port := cfg.Get[int]("port")       // хотим int
host := cfg.Get[string]("host")     // хотим string
```
Тип возврата зависит от того, что попросили — значит методу нужен свой параметр `T`. Именно `[T ...]` после имени метода и было запрещено.

Приходилось выносить в функцию пакета, хотя по смыслу это операция конфига:
```go
port := GetFromConfig[int](cfg, "port")   // вместо cfg.Get[int]("port")
```

В 1.27 запрет сняли. Пример из релиза: в `math/rand/v2` рядом с функцией `N[Int intType](Int) Int` появился метод:
```go
func (r *Rand) N[Int intType](n Int) Int

x := r.N[int](100)   // случайное int от 0 до 99
```

Что осталось нельзя: объявлять методы с type-параметрами **в интерфейсах**, и дженерик-метод не может реализовать метод интерфейса.
```go
type Mapper interface {
    Map[U any](f func(int) U) U   // ❌ так нельзя даже в 1.27
}
```
Причина: чтобы вызвать метод через интерфейс, компилятор должен заранее знать конкретный набор методов (Method Set) — а какой именно `U` подставят при вызове, заранее не известно, это решается только в момент компиляции конкретного вызова у конкретного типа. Фича работает только для методов **конкретных** (не интерфейсных) типов.

## 2. `encoding/json/v2` — новый JSON-движок

Более строгий по умолчанию: отклоняет невалидный UTF-8 и дублирующиеся ключи объекта.

**Было (`encoding/json`, v1) — молча пропускало проблемы:**
```go
data := []byte(`{"name": "Alice", "name": "Bob"}`)  // дублирующийся ключ
var u User
json.Unmarshal(data, &u)
// u.Name == "Bob" — просто взял последнее значение, без ошибки
```

**Стало (`encoding/json/v2`) — падает с ошибкой:**
```go
import "encoding/json/v2"

data := []byte(`{"name": "Alice", "name": "Bob"}`)
var u User
err := json.Unmarshal(data, &u)
// err != nil: duplicate object key "name"
```

Старый `encoding/json` теперь сам работает **поверх** v2-реализации — v1 API остаётся доступным и совместимым (со старым, более терпимым поведением), просто под капотом другой движок.

## 3. Goroutine leak profiling — теперь официальная фича (не experimental)

`runtime/pprof` отдаёт профиль `goroutineleak` — находит горутины, навсегда заблокированные на канале/мьютексе/похожем примитиве.

**Было (до 1.27) — искали утечки вручную или сторонними библиотеками:**
```go
import "go.uber.org/goleak"

func TestMain(m *testing.M) {
    goleak.VerifyTestMain(m)   // сторонний пакет, только в тестах
}
```

**Стало (1.27+) — встроено в стандартный pprof:**
```go
import _ "net/http/pprof"
// доступно прямо в проде: http://localhost:6060/debug/pprof/goroutineleak
```

Прямо закрывает классическую проблему — например, `time.After` в цикле или `defer` внутри цикла, которые раньше приходилось ловить вручную по метрикам или сторонними пакетами (см. «Гошка», вопросы про горутины и `defer`).

---

## 4. Ускорение мелких аллокаций — до 30%

Компилятор генерирует size-specialized процедуры аллокации для объектов **до 80 байт**. Прирост ~30% на таких аллокациях, ~1% в среднем на аллокационно-тяжёлых программах. Цена — бинарник крупнее на ~60 КБ. Ничего не нужно менять в коде — это чисто компиляторная оптимизация (можно отключить через `GOEXPERIMENT=nosizespecializedmalloc`, если нужно сравнить со старым поведением).

## 5. Post-quantum криптография — `crypto/mldsa`

**Было (до 1.27) — только сторонние библиотеки:**
```go
import "github.com/cloudflare/circl/sign/mldsa/mldsa65"  // сторонний пакет
```

**Стало (1.27+) — в стандартной библиотеке:**
```go
import "crypto/mldsa"

pub, priv, err := mldsa.GenerateKey(mldsa.MLDSA65, rand.Reader)
sig := mldsa.Sign(priv, message)
ok := mldsa.Verify(pub, message, sig)
```
Поддержка и в `crypto/x509` (сертификаты), и в `crypto/tls` (TLS 1.3, схемы `MLDSA44`/`MLDSA65`/`MLDSA87`).

## 6. Мелкие, но полезные изменения

**Пакет `uuid`:**

*Было* — сторонний пакет:
```go
import "github.com/google/uuid"

id := uuid.New()
```
*Стало* — в стандартной библиотеке:
```go
import "uuid"

id := uuid.New()
fmt.Println(id.String())
```

**`bytes.CutLast()` / `strings.CutLast()`** — режет по **последнему** вхождению разделителя.

*Было* — только `Cut`, режущий по **первому** вхождению, для последнего нужен был `LastIndex` + ручной срез:
```go
i := strings.LastIndex("a/b/c.txt", "/")
before, after := "a/b/c.txt"[:i], "a/b/c.txt"[i+1:]
// before = "a/b", after = "c.txt"
```
*Стало* — готовая функция:
```go
before, after, found := strings.CutLast("a/b/c.txt", "/")
// before = "a/b", after = "c.txt", found = true
```

**`testing/synctest.Sleep()`** — совмещает `time.Sleep` + `synctest.Wait`, удобно в тестах конкурентного кода:
```go
synctest.Sleep(2 * time.Second)
```

**`httptest.NewTestServer()`** — тестовый сервер на in-memory фейковой сети, без реального сокета.

*Было* — `httptest.NewServer` открывает настоящий TCP-порт:
```go
srv := httptest.NewServer(handler)   // реальный сокет на localhost
```
*Стало* — можно без сокета вообще:
```go
srv := httptest.NewTestServer(handler)   // in-memory, без реальной сети
```

**`go doc package@version`** — можно смотреть документацию конкретной версии пакета без её установки:
```
go doc golang.org/x/text@v0.15.0
```

---

## 7. Платформенные изменения

- Требуется **macOS 13 Ventura+** — более старые версии больше не поддерживаются тулчейном.
- SIMD-пакеты (`simd`, `simd/archsimd`) остаются **experimental**, но расширили поддержку архитектур (arm64 Neon, WebAssembly).

---

## Итог — что реально стоит запомнить для интервью

1. **Generic methods** — методы могут иметь свои type parameters, кроме методов интерфейсов.
2. **`encoding/json/v2`** — новый, более строгий JSON-движок (падает на дублирующихся ключах/невалидном UTF-8), старый API работает поверх него.
3. **`goroutineleak` профиль** — встроенный детектор утечек горутин, вышел из experimental, не нужен сторонний `goleak`.
4. Мелкие аллокации (<80 байт) — быстрее до 30%, бесплатно, без изменений в коде.

# Go 1.26 — что нового (предыдущий релиз, вышел 10 февраля 2026)

## 1. Green Tea GC — новый сборщик мусора, теперь по умолчанию

Был экспериментальным, в 1.26 включён **по умолчанию** для всех программ, без флагов.

- **Снижает накладные расходы GC на 10-40%** — самое заметное изменение производительности за последние релизы.
- Плюс ~10% на новых amd64-платформах (Intel Ice Lake, AMD Zen 4+) за счёт векторных инструкций.
- Ничего не нужно менять в коде — чистая рантайм-оптимизация. Отключить (для сравнения) можно через `GOEXPERIMENT=nogreenteagc`.

## 2. Self-referential generic types — тип может ссылаться сам на себя в ограничении

**Было (до 1.26) — не компилировалось:**
```go
// ❌ ошибка: тип не мог упоминать себя в собственном constraint
type Adder[A Adder[A]] interface {
    Add(A) A
}
```

**Стало (1.26+) — работает:**
```go
type Adder[A Adder[A]] interface {
    Add(A) A
}

func algo[A Adder[A]](x, y A) A {
    return x.Add(y)
}
```
Полезно для паттернов вида "метод возвращает тот же тип, что и получатель" (fluent-API, builder-цепочки), где тип сам себя ограничивает.

## 3. `new()` теперь принимает выражение, не только тип

**Было:**
```go
age := 25
p := new(int)
*p = age
```

**Стало:**
```go
p := new(25)          // сразу указатель на значение
Age: new(yearsSince(born))   // удобно для опциональных полей в структуре
```

## 4. Goroutine leak profile — появился как experimental (в 1.27 стал официальным)

```go
// GOEXPERIMENT=goroutineleakprofile
// доступно на /debug/pprof/goroutineleak
```
Ровно та функция, которая в нашем разборе 1.27 выше уже официальная и включена по умолчанию — в 1.26 это был её экспериментальный дебют.

## 5. `crypto/*` — рандомные параметры больше не учитываются

В `crypto/rand`, `crypto/rsa`, `crypto/ecdsa`, `crypto/ed25519` и др. — если раньше можно было передать свой `io.Reader` вместо системного источника случайности, теперь эти параметры **игнорируются**, всегда используется безопасный криптографический ГПСЧ. Для детерминированных тестов — новый пакет `testing/cryptotest.SetGlobalRandom()`. Старое поведение можно вернуть через `GODEBUG=cryptocustomrand=1`.

## 6. `go fix` — полностью переписан

Новый набор "modernizers" — автоматически обновляют код под актуальные идиомы и API, плюс source-level инлайнер через директиву `//go:fix inline`.

---

## Итог по 1.26 — что стоит запомнить

1. **Green Tea GC по умолчанию** — минус 10-40% накладных расходов на GC, без изменений в коде.
2. **Self-referential generic constraints** — тип может ограничивать себя через себя же (`Adder[A Adder[A]]`).
3. **`goroutineleak` профиль дебютировал здесь** как experimental — в 1.27 стал официальным.
4. **`crypto/rand` и друзья** — больше нельзя подсунуть свой источник случайности, только безопасный системный.

# Go 1.25 — что нового (вышел 12 августа 2025)

## 1. Container-aware GOMAXPROCS

Раньше `GOMAXPROCS` считался по числу CPU **хоста**, даже если процесс запущен в контейнере с урезанным CPU-лимитом (частая проблема в k8s — приложение видело 32 ядра хоста, хотя реально ему выделено 2, и создавало слишком много OS-потоков).

**Стало (1.25+):** рантайм на Linux сам учитывает cgroup CPU-лимиты и выставляет `GOMAXPROCS` под реально доступные ядра, плюс периодически обновляет значение, если лимит меняется на лету (например, при горизонтальном автомасштабировании ресурсов пода). Отключается через `GOMAXPROCS` env-переменную, вызов `runtime.GOMAXPROCS()` вручную, либо `GODEBUG=containermaxprocs=0`.

## 2. `sync.WaitGroup.Go()` — удобный запуск горутины со счётчиком

**Было (до 1.25):**
```go
var wg sync.WaitGroup
wg.Add(1)
go func() {
    defer wg.Done()
    work()
}()
```

**Стало (1.25+):**
```go
var wg sync.WaitGroup
wg.Go(func() {
    work()
})
```
`Go()` сам делает `Add(1)`, запускает горутину и гарантированно вызывает `Done()` по завершении — меньше шансов забыть `Add`/`Done` или напутать порядок (см. «Гошка», вопрос про `WaitGroup` и `sync.Pool`).

## 3. `testing/synctest` — из эксперимента в стандартную библиотеку

Виртуализированное время в тестах конкурентного кода — тест с `time.Sleep(1*time.Hour)` внутри выполняется мгновенно, если все горутины "бублика" заблокированы:
```go
testing.synctest.Test(t, func(ctx context.Context) {
    // время виртуализировано — fake clock сама "прыгает" вперёд,
    // когда все горутины заблокированы (на sleep, канале и т.д.)
})
```
(Это тот же пакет, для которого в 1.27 выше добавили удобный `synctest.Sleep()`.)

## 4. Исправлен старый компиляторный баг с nil pointer (жил с 1.21)

**Было (баг, 1.21–1.24) — проверка на nil откладывалась некорректно:**
```go
f, err := os.Open("nonExistentFile")
name := f.Name()   // f == nil, но паники здесь могло не случиться из-за бага компилятора
if err != nil {
    return
}
```
**Стало (1.25+):** компилятор больше не переставляет местами разыменование и проверку — паника происходит именно там, где реально разыменовывается nil, без "магического" исчезновения.

## 5. Green Tea GC — экспериментальный дебют

Именно здесь появился тот самый сборщик мусора, который в 1.26 стал дефолтным (`GOEXPERIMENT=greenteagc`) — заявленные 10-40% снижения накладных расходов GC уже были в этом релизе, просто под флагом.

---

## Итог по 1.25 — что стоит запомнить

1. **Container-aware GOMAXPROCS** — рантайм сам учитывает cgroup CPU-лимиты в контейнерах/k8s, не только CPU хоста.
2. **`WaitGroup.Go()`** — обёртка над `Add`/`go func`/`defer Done()`, меньше шансов ошибиться.
3. **`testing/synctest`** вышел из experimental — виртуализированное время в тестах конкурентного кода.
4. **Green Tea GC** дебютировал здесь как experimental — годом позже (1.26) стал дефолтным.

# Go 1.24 — что нового (вышел 11 февраля 2025)

## 1. Swiss Tables — новая реализация мапы в рантайме

Встроенная `map` переехала на алгоритм **Swiss Tables** (из Abseil): вместо цепочки бакетов по 8 элементов — группы слотов с компактной таблицей контрольных байтов, которые сравниваются пачкой (SIMD-подобно).

- Поиск в больших мапах быстрее, меньше промахов кеша; по релизным замерам — до **−30% времени** на операциях с крупными мапами и ~2-3% общего выигрыша CPU в среднем приложении.
- Семантика не поменялась: порядок итерации по-прежнему случайный, потокобезопасности как не было, так и нет.
- Заодно переписали `sync.Map` (на HashTrieMap) и ускорили выделение мелких объектов.

Отключалось через `GOEXPERIMENT=noswissmap` (см. «Гошка», вопрос про мапы).

## 2. `os.Root` — работа с файлами в границах каталога

Защита от path traversal (`../../etc/passwd`) прямо в стандартной библиотеке:
```go
root, err := os.OpenRoot("/srv/uploads")
if err != nil {
    return err
}
defer root.Close()

f, err := root.Open(userProvidedName) // выйти за пределы /srv/uploads нельзя
```
Все операции (`Open`, `Create`, `Stat`, `Remove`) резолвятся относительно корня, символические ссылки наружу не работают.

## 3. `testing.B.Loop()` — правильный бенчмарк-цикл

**Было:**
```go
for i := 0; i < b.N; i++ {
    result = process(input) // нужен внешний sink, иначе компилятор выкинет вызов
}
```
**Стало (1.24+):**
```go
for b.Loop() {
    process(input)
}
```
- Компилятор не выбрасывает тело цикла — sink-переменные и `runtime.KeepAlive` не нужны.
- Код до первого `b.Loop()` и после цикла считается setup/teardown и **не входит в замер**, таймер не надо останавливать руками.
- Функция вызывается ровно столько раз, сколько нужно рантайму бенчмарка.

## 4. Generic type aliases — алиасы с параметрами типа

```go
type Set[T comparable] = map[T]struct{}
```
Раньше параметризованными могли быть только определения типов (`type Set[T] map[T]struct{}`), теперь и алиасы — удобно для постепенного переезда пакетов и коротких имён для generic-типов.

## 5. Директива `tool` в `go.mod` — конец файлу `tools.go`

**Было:** костыль с `//go:build tools` и пустыми импортами, чтобы зафиксировать версии `mockery`, `golangci-lint`, `protoc-gen-go`.

**Стало:**
```bash
go get -tool github.com/vektra/mockery/v3
go tool mockery          # запуск
go tool                  # список инструментов проекта
```
Инструменты записываются директивой `tool` в `go.mod` и версионируются вместе с проектом.

## 6. `weak` и `runtime.AddCleanup` — слабые ссылки и финализаторы по-человечески

- Пакет `weak` — слабые указатели: объект доступен, пока жив, но не удерживает его от GC. Основное применение — кеши, которые не должны течь.
- `runtime.AddCleanup` — замена `runtime.SetFinalizer`: можно вешать несколько функций на объект, не мешает освобождению циклов и не «воскрешает» объект.

## 7. Мелкие, но полезные изменения

- **`omitzero` в JSON-тегах** — `json:"date,omitzero"` пропускает нулевое значение типа (в отличие от `omitempty`, который не умел в `time.Time{}` и структуры).
- **Итераторные хелперы**: `strings.SplitSeq`, `strings.FieldsSeq`, `strings.Lines`, аналоги в `bytes` — `range` по строкам без выделения слайса.
- **`crypto/mlkem`, `crypto/hkdf`, `crypto/pbkdf2`, `crypto/sha3`** приехали в stdlib; появился FIPS 140-3 режим (`GODEBUG=fips140=on`).
- **`testing/synctest`** дебютировал как эксперимент (`GOEXPERIMENT=synctest`) — в 1.25 стал обычным пакетом.
- **`encoding.TextAppender` / `BinaryAppender`** — сериализация в существующий буфер без лишних аллокаций.
- **`go build` пишет информацию из VCS** в бинарник (версия, коммит) — видно через `go version -m`.
