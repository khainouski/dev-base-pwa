# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

DevBase — личное PWA для подготовки к техническим собеседованиям: вопросы и собственные
ответы владельца (Go, базы данных, микросервисы, инфраструктура, процесс и лидерство),
у каждого вопроса две кнопки к AI — «Пример» и «Уточнить». Без сборки, без бандлера,
без бэкенда, без тестов — браузер грузит ES-модули как они лежат на диске.

Сделано по образцу соседнего `../ai-base-pwa`: оболочка, настройки, установка на телефон
и слой AI пришли оттуда.

## Commands

```bash
npm run dev      # статика на http://localhost:3000 (npx serve)
```

`file://` не годится: service worker и модули требуют `http://`.

Деплой — Vercel без сборки (Framework Preset **Other**, пустые build command и output
directory); `vercel.json` задаёт заголовки кэша.

## Critical: поднимать `VERSION` в `sw.js`

`sw.js` перечисляет оболочку руками — каждый файл `js/`, `css/`, иконки **и каждый
конспект `data/md/**.md`**. После добавления, переименования или удаления файла допиши
его в `SHELL` **и** подними `VERSION` (`v1` → `v2`), иначе установленные копии продолжат
отдавать старый кэш. Это самый частый способ сломать изменение в этом репозитории.

## Содержание: markdown, а не JS

Текст лежит в `data/md/<папка>/<страница>.md` — ровно теми файлами, которые владелец
пишет для себя. Переносить их в JS-литералы нельзя: файлы большие, правятся часто,
и любой такой перенос означал бы расхождение между конспектом и приложением.
`data/content.js` хранит только оглавление: какие папки есть, какие в них страницы,
как они называются в интерфейсе и в каком порядке.

Шаблон файла конспекта — тот, в котором владелец их уже пишет:

```markdown
# Заголовок файла          ← необязателен, показывается подзаголовком страницы
## Содержание              ← выбрасывается: навигацию рисует само приложение
## Вопросы и ответы        ← заголовок-обёртка, на экране не показывается
## Раздел                  ← необязателен; без него будет один безымянный раздел
### Q1. Текст вопроса      ← нумерация `### 1.` тоже понимается
ответ в обычном markdown
---
### Q2. Текст вопроса {gen}   ← ответ написан моделью, а не владельцем
```

`{gen}` в конце заголовка вопроса ставит на странице пометку **AI**: это сигнал, что
ответ сгенерирован и его стоит перечитать, а не заучивать как свой. У вопроса без
ответа тело просто пустое — страница предложит спросить модель кнопками.

Страница-справочник (`kind: 'doc'` в `FOLDERS`) на вопросы не разбита: она рисуется
одним куском, с общей панелью AI внизу. Так сделаны «Пакеты stdlib» и «Релизы Go».

Добавить страницу — положить файл в `data/md/<папка>/`, дописать строку в `FOLDERS`
(`data/content.js`), дописать путь в `SHELL` и поднять `VERSION` в `sw.js`.

## Architecture

Хэш-роутер → вьюхи → общие помощники → хранилище и AI.

- **`js/router.js`** — точка входа. Разбирает `#/kind/a/b/c` (`f` папка, `p` страница,
  `settings`), чистит `#app`, зовёт одну `render*(root, ...)`. Здесь же поиск: индекс
  строится **лениво**, при первом открытии поля, — вопросы лежат в файлах конспектов,
  и тянуть их все ради экрана, на который могут не зайти, незачем.
- **`js/views/*.js`** — по экрану на файл, каждый экспортирует `async render*(root, ...)`.
  Вьюхи собирают HTML строками: фреймворка и виртуального DOM нет.
  `practice.js` — не маршрут, а панель AI (`mountQuestionAi(slot, ctx)`) под каждым вопросом.
- **`js/markdown.js`** — разбор и отрисовка конспектов. `parseNotes()` режет файл на
  разделы и вопросы, `renderMd()` рисует тело ответа, `inline()` — одну строку,
  `stripToc()` снимает «Содержание» со страниц-справочников.
  Поддерживается ровно тот поднабор markdown, которым написаны сами заметки: заголовки,
  списки с вложенностью, таблицы, блоки кода, цитаты, `код`, **жирный**, ссылки.
  Всё проходит через `esc()`.
- **`data/content.js`** — `FOLDERS` (папка → страницы) и `loadPage()`: файл читается по
  сети один раз и остаётся в памяти.
- **`js/storage.js`** — единственный слой хранения (`localStorage`, префикс `devbase:`).
  API асинхронный намеренно. Здесь же `PROVIDERS` (провайдеры, их модели и ссылки на ключи)
  и `LEVELS` — как объяснять.
- **`js/ai.js`** — все вызовы модели. Два адаптера (Anthropic Messages API и Gemini) за
  одним `ask(prompt, { temperature })`, оба отдают разобранный JSON. Ключ идёт заголовком;
  для Anthropic из браузера обязателен `anthropic-dangerous-direct-browser-access`.
  HTTP-статусы превращаются в русский `AiError` с `code`.
- **`js/prompts.js`** — все промпты. В каждый уходит сам вопрос и записанный под ним
  ответ: модель объясняет то, что у владельца записано, а не предмет вообще.
  Новый AI-режим добавляется сюда, а не внутрь вьюхи.
- **`js/ui.js`** — строковые помощники: `esc` (всегда экранировать текст модели), `el`,
  `mdLite`, `crumbs`, `rowList`, `loading`, `errorBox`, `toast`, `plural`, `copyText`.
- **`js/pwa.js` / `js/install.js`** — регистрация SW, перезагрузка по `controllerchange`
  (подавляется, пока пользователь печатает), баннер установки для iOS.

## Conventions

- Интерфейс, ошибки и комментарии — по-русски; английскими остаются термины, код, флаги
  и имена файлов. Комментарии объясняют *почему*, а не пересказывают код.
- Конспект — источник: не переписывай формулировки владельца под «как принято в учебниках».
- Никаких зависимостей, фреймворков и TypeScript. Обычные ES-модули с относительными
  путями и расширением `.js`.
- Всё, что пришло от модели, — недоверенный текст: только через `esc()` или `mdLite()`.
- Запись в `localStorage` может бросить (приватный режим Safari); `storage.js` это гасит,
  приложение обязано работать и без хранилища.
- Каждый экран ниже корня рисует `crumbs()`: с домашнего экрана это единственный выход.
  `js/router.js` нумерует записи истории в `history.state.devbase`, чтобы ссылка делала
  настоящий `history.back()`, а в позиции 0 уходила по своему `href`.
